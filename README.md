# HH Apply Bot

Локальное приложение для поиска вакансий HH.ru, оценки соответствия профилю и запуска откликов из интерфейса. Next.js 16, React 19, TypeScript, Prisma 7, SQLite, Playwright.

## Быстрый запуск

Нужен Node.js 22.12+ (ветка 22 LTS) или 24+. Версия для nvm указана в `.nvmrc`.

```bash
npm ci
cp .env.example .env  # только при первой установке
npm run setup
npm run dev
```

Откройте http://localhost:3000. В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env`. Не перезаписывайте существующий `.env` при обновлении.

В Windows `install-and-run.cmd` или `Запустить HH Bot.cmd` устанавливает зафиксированные зависимости, применяет готовые миграции, загружает Chromium и запускает приложение. Скрипты работают из текущей папки проекта. Если есть portable Node в `.tools/node-v22.23.1-win-x64`, он используется автоматически. Для повторного запуска достаточно `start-project.cmd`.

Для готовой сборки:

```bash
npm run build
npm start
```

Приложение рассчитано на один локальный процесс Node.js. Состояние длительных задач хранится в памяти процесса; при его перезапуске запущенная задача прекращается. Для нескольких процессов или серверного размещения потребуется отдельная очередь задач.

## Интерфейс и управление данными

На странице «Обзор» показатели открывают списки вакансий с соответствующим статусом; «Откликов сегодня» учитывает дату отправки отклика, а не дату добавления вакансии. Здесь же показаны действующие условия поиска и подтверждённый профиль HH. После проверки входа кнопка авторизации заменяется именем профиля и кнопкой выхода. Выход очищает локальную сессию бота и доступен после завершения текущего процесса.

В таблице доступны поиск, статус, компания, город, наличие зарплаты, минимальное совпадение, период, последний поисковый пакет и отклики за сегодня. Фильтры, сортировка и страницы сохраняются в URL и применяются ко всей базе. Выбранные строки можно пропустить, вернуть в очередь, удалить, выгрузить в CSV или запустить отклики только по их ID. Отправленные отклики не переводятся обратно в очередь групповым действием. Удаление требует подтверждения, а изменение очереди блокируется во время работы бота.

Логи поддерживают поиск по сообщению и подробностям, фильтр уровня и периода, сортировку по времени и постраничный просмотр. Удаляется либо явный список выбранных записей, либо подтверждённая выборка по применённым фильтрам. Даты и границы «сегодня» используют Europe/Moscow.

В автооткликах число можно вводить с клавиатуры, выбирать ползунком или готовой кнопкой. Настройки разделены на резюме, условия поиска, лимиты и паузы, профиль и сопроводительное письмо. Сохранение доступно в закреплённой панели.

## Авторизация и встроенный браузер

1. На Dashboard нажмите «Войти в HH». Страница входа появится внутри интерфейса бота.
2. Нажимайте поля и печатайте прямо на странице; поддерживаются вставка текста, Tab, Enter, прокрутка и перетаскивание. Для телефона и сложного ввода есть отдельное поле «Текст для выбранного поля HH». При входе его содержимое скрыто.
3. Дождитесь подтверждения аккаунта (профиль пользователя или защищённая страница «Мои резюме»). Учитывается `/applicant/profile/me`. Только после подтверждения сессия сохраняется в `hh-auth.json`. Отсутствие кнопки входа само по себе не считается авторизацией.
4. Во время поиска и откликов страница HH показывается в том же встроенном браузере, а панель бота над ней сообщает статус и прогресс. «Свернуть» оставляет компактную кнопку и приостанавливает передачу изображения. Новая ручная проверка раскрывает панель снова.

Chromium всегда запускается без отдельного окна, включая ручной вход. Сохранённое ранее `browserHeadless=false` больше не открывает окно на рабочем столе; поле оставлено в базе для совместимости. После завершения задачи браузер закрывается. При истёкшей сессии работа останавливается с предложением нажать «Войти в HH». Старые переменные `HH_HEADLESS` и `HH_ACTION_DELAY_*` не используются; задержки задаются в Settings.

CAPTCHA решает только пользователь. Бот не закрывает браузер и не завершает задачу: текущая страница, выбранное резюме и прогресс сохраняются, пока вы проходите проверку. Ожидание CAPTCHA не ограничено по времени и прерывается кнопкой Stop. После решения нажмите «Проверить и продолжить». Исчезновение виджета само по себе не снимает паузу. После отправки бот остаётся на той же странице и ждёт подтверждения HH; форму не заменяет переходом на другую страницу и отправку повторно не нажимает. Если HH оставил вопросы, требования к резюме или другую незавершённую форму, очередь продолжает ждать ручного завершения даже после нажатия «Продолжить».

CAPTCHA и незнакомые формы открываются в том же встроенном браузере. Во время автоматизации доступен просмотр; управление включается при входе или ручной паузе, чтобы действия пользователя не пересекались с отправкой отклика. Команды привязаны к странице и номеру паузы: запоздалые нажатия не переходят на следующую проверку. Бот не меняет видимость резюме и не отвечает на вопросы работодателя самостоятельно. Пока задача ждёт, новые отклики не отправляются.

Ошибка загрузки, HTTP 403 или промежуточная пустая страница не закрывают страницу входа: нажмите «Перезагрузить HH» внутри панели. Ожидание входа длится до 10 минут; затем страница остаётся доступной, а проверку входа можно повторить кнопкой «Войти в HH». Stop закрывает браузер по вашей команде. Неудачная попытка входа не перезаписывает сохранённую сессию. Автоотклики начинаются только после нажатия Start в интерфейсе.

## Списки, стоп-фразы и ответы

Выпадающие списки построены на Radix UI: единое оформление, управление стрелками, Enter и Escape, размещение внутри экрана. Правый клик по строке вакансии открывает меню «Не интересует…». В небольшом всплывающем редакторе можно ввести отдельное слово или фразу, очистить ввод и удалить сохранённые стоп-фразы крестиком. Сохранение добавляет фразу только в текущее резюме и пропускает выбранную вакансию; отправленные отклики не меняются.

Во вкладке «Ответы» кнопка «Обновить из HH» читает список откликов и тексты чатов текущего аккаунта. Поддерживаются поиск по компании, вакансии и тексту, положительные/отрицательные ответы, прочитанность, выбор текущего резюме или всего аккаунта, сортировка и период загрузки. Приглашения и отказы распознаются по статусу HH, однозначные входящие сообщения — по тексту; остальные остаются нейтральными. Переписка хранится отдельно для каждого HH-аккаунта. При отсутствии ссылки на резюме в HH-чате фильтр текущего резюме использует подтверждённую историю отправленных ботом откликов.

Синхронизация не отправляет сообщений и откликов. Открытие чата может отметить его прочитанным в HH. За один запуск читается до 100 последних диалогов, в каждом сохраняются до 100 доступных сообщений; старые снимки не стираются при временной ошибке загрузки. CAPTCHA ждёт действия во встроенном браузере, Stop сохраняет уже загруженные ответы.

Новая установка не содержит резюме, поисковых запросов, стоп-слов, зарплаты или ограничения по городу. Изначально поиск ведётся по всей России с любым форматом работы. Данные скрипта `prepare-ui-fixture.mjs` вымышлены и попадают только в отдельную базу `test-results`, никогда в обычный запуск приложения. Личные SQLite-базы, сессии HH и резервные копии исключены из Git.

## Несколько резюме

В боковой панели выберите рабочее резюме или нажмите «Добавить резюме». Достаточно ссылки HH: название берётся из заголовка резюме, а ключевые слова, город, зарплата, формат работы и текст для подбора заполняются при разборе. Вводить отдельное название не нужно. Можно скопировать фильтры и лимиты текущего резюме; его история, сопроводительное письмо и текст резюме не копируются. Если HH требует вход или CAPTCHA, разбор ждёт действия во встроенном браузере. Резюме добавляется после проверки в разделе «Мои резюме» авторизованного аккаунта. Чужая публичная ссылка не подходит: при ошибке проверки новый профиль не создаётся. Перед отправкой откликов принадлежность резюме проверяется заново; она также проверяется при сохранении другой ссылки в настройках.

Каждое резюме имеет собственные настройки, поисковые запросы, найденные вакансии, match score, историю откликов, логи, дневной лимит и статистику. Одинаковая ссылка вакансии может встречаться в разных профилях. Отправленный из другого профиля отклик повторно не отправляется. Вход HH остаётся общим. Смена профиля во время задачи заблокирована, а несохранённые правки требуют подтверждения перед переходом. Старая вкладка не может сохранить настройки поверх другого активного резюме.

Миграция переносит прежние данные в первое резюме без удаления истории. Для его названия используется должность из ранее загруженного резюме; при необходимости повторите разбор ссылки HH. Смена рабочего резюме сохраняется между перезапусками.

## Разбор резюме по ссылке

В Settings рядом с «Загрузить из HH» есть «Распарсить по ссылке». Кнопка читает резюме HH и предлагает ключевые слова из желаемой должности, город проживания, желаемую месячную зарплату в рублях, формат работы и текст для подбора вакансий. Поддерживаются разные профессии и старый и новый вид страницы HH.

Если значения отличаются от уже заполненных, появится сравнение с выбором «Заменить заполненные поля», «Заполнить только пустые» или «Отмена». Учитываются и несохранённые изменения в форме. В режиме «Только пустые» сохраняется выбранный формат работы, в том числе снятая галочка. Ненайденные поля не очищаются; зарплата в другой валюте или с почасовой оплатой остаётся для ручного заполнения. Данные сначала подставляются в форму, запись настроек выполняется только кнопкой «Сохранить». Во время поиска или откликов разбор не прерывает текущую задачу: сначала остановите её.

## Поиск и запрещённые слова

В Settings задайте ключевые слова, города или поиск по всей России, формат работы, зарплату, количество новых вакансий и задержки. Подходит любая профессия: водитель, врач, бухгалтер, повар, инженер, разработчик и другие. Встроенных списков разрешённых или нежелательных профессий нет; новые профили создаются с пустыми поисковыми запросами и резюме. Существующие настройки сохраняются.

Каждый поисковый запрос — отдельная альтернатива. Ручные запросы всегда имеют приоритет и сохраняются при импорте резюме. Если список пуст, запрос берётся из строки «Желаемая должность: …» в профиле или из заголовка импортированного резюме HH. Можно указать несколько желаемых должностей через `/` или `;`. Опыт работы и случайное упоминание навыка не заменяют желаемую профессию. Учитываются и название, и полное описание вакансии, поэтому поиск по навыкам также работает.

Запрещённые слова и фразы вводятся с новой строки, через запятую или точку с запятой. Фильтр проверяет название, компанию, город, зарплату и полное описание вакансии. Краткий текст карточки используется только для предварительного отбора; перед сохранением читается страница вакансии. Исключений для управленческих должностей нет.

Сопоставление игнорирует регистр, различие «ё/е», невидимые символы и разделители между словами. Для русских слов используется сопоставление по основе: «стажёр» блокирует «стажёра», «холодные звонки» — «холодных звонков». Это эвристика, а не полноценный морфологический анализ. Английские слова сопоставляются целиком: `Java` не блокирует `JavaScript`.

Перед каждым ручным и автоматическим откликом фильтр повторно применяется к сохранённой вакансии и к свежему полному описанию. Запрещённая вакансия получает статус `skipped`. Если полное описание недоступно, отклик не отправляется. Для изменения настроек сначала остановите текущую задачу.

Повторный поиск не возвращает уже принятые вакансии, даже если их удалили из списка: ссылки остаются в `SeenVacancy`. Автоотклики работают с последней поисковой подборкой, включая сохранённую часть поиска, остановленного пользователем.

## Выбор резюме и отклики

Перед Start на странице Auto Apply выберите «Пропускать вакансии с дополнительными требованиями». Включённый чекбокс пропускает вопросы работодателя, анкеты и требования к видимости резюме, ставит вакансии статус «Пропущена» и продолжает очередь без расходования числа новых откликов. По умолчанию чекбокс снят: бот ждёт ручного завершения формы во встроенном браузере. Режим задаётся перед запуском и не меняется во время цикла. CAPTCHA всегда ожидает ручного решения; незнакомая форма без распознанных требований также остаётся для ручной проверки.

Перед отправкой бот открывает форму отклика, сравнивает все доступные резюме и подтверждает выбранный вариант. Быстрая кнопка на странице вакансии может отправить отклик с последним резюме HH, поэтому бот использует отдельную форму выбора.

Оценка использует один алгоритм для любой профессии: сравниваются слова, специальности и навыки в названиях доступных резюме с названием и описанием вакансии. Учитываются русские формы слов и односимвольные категории водителей B/C. Добавление другой альтернативной профессии в настройки не снижает оценку уже подходящей вакансии. Название вакансии имеет больший вес, чем случайное упоминание технологии в описании. При заданной ссылке HH бот выбирает именно резюме активного профиля; другое резюме с более высоким совпадением его не заменяет. Если HH не позволяет однозначно определить нужное резюме, очередь ждёт ручного выбора и отправки в той же форме. Без ссылки применяется сравнение доступных названий. Единственное доступное резюме также поддерживается. Это детерминированный подбор по названиям, без внешней AI-службы. Оценки вариантов и выбранное резюме записываются в логи.

Ручной отклик запускается в Vacancies. Автоотклики — в Auto Apply, кнопкой Start. Дневной лимит действует в обоих режимах. Запрещённые вакансии и неудачные попытки не расходуют заданное количество успешных откликов. Stop останавливает задачу после текущего безопасного шага. Подтверждённый HH отклик сохраняется вместе со статусом вакансии в одной транзакции.

Статусы: `found` / `pending` — ожидают обработки, `applied` — отправлен или уже был отправлен, `skipped` — пропущен вручную или фильтром, `failed` — ошибка. Необходимость дополнительных ответов в форме HH фиксируется как ошибка без выдумывания ответов.

## Настройки окружения и база

```env
DATABASE_URL="file:./dev.db"
HH_STORAGE_STATE_PATH="./hh-auth.json"
HH_DEFAULT_CITY="Москва"
```

Относительный `DATABASE_URL` по-прежнему разрешается от папки `prisma`, поэтому `file:./dev.db` указывает на существующий `prisma/dev.db`. Prisma CLI и приложение используют один resolver. Адаптер SQLite сохраняет совместимый с прежним Prisma формат дат `unixepoch-ms`.

Для установки и обновления используйте `npm run prisma:deploy` (входит в `npm run setup`). `npm run prisma:migrate` предназначен для разработки новых миграций. Перед обновлением существующей базы сделайте резервную копию; не используйте `migrate reset` для рабочей базы. Копия базы до этого обновления находится в `prisma/backups/` и исключена из Git.

## Проверки и разработка

```bash
npm run check       # ESLint, TypeScript, регрессионные тесты, production build
npm run test:watch  # тесты при изменении кода
npm run smoke       # проверка страниц и API уже запущенного localhost:3000
npm run smoke:resume # проверка диалога разбора на синтетическом резюме без записи настроек
npm run smoke:auto   # проверка запуска и режима дополнительных требований
```

`SMOKE_BASE_URL` позволяет проверить другой локальный порт. Smoke-проверка только читает страницы и API; поиск и отклики не запускаются. Тесты Playwright используют локальные макеты HH и отдельный файл сессии в `test-results`, не читают рабочую сессию и не отправляют настоящих откликов.

Зависимости зафиксированы в `package-lock.json`. Prisma CLI, клиент и адаптер обновляются вместе; используются стабильные версии Prisma 7. Для TypeScript и ESLint выбраны версии, совместимые с текущим `eslint-config-next`.

```text
src/app/                    страницы и HTTP API
src/components/             интерфейс
src/lib/hh/runner.ts         управление задачами, лимитами и сохранением результатов
src/lib/hh/browser-session.ts запуск браузера, авторизация, остановка и закрытие
src/lib/hh/playwright.ts     чтение HH и работа с формами
```

Для изменений автоматизации запускайте тесты фильтра, выбора резюме, runner и браузерных форм. После обновления Playwright обновляйте Chromium через `npx playwright install chromium`. Проверяйте миграции на отдельной базе; существующие миграции не переписывайте.

Полный тест интерфейса с удалением выполняется только на отдельной вымышленной базе:

```bash
npm run build
node scripts/prepare-ui-fixture.mjs
DATABASE_URL="file:$PWD/test-results/workspace-ui/fixture.db" HH_STORAGE_STATE_PATH="$PWD/test-results/workspace-ui/hh-auth.json" npm run start -- --port 3011
# В другом терминале:
SMOKE_BASE_URL=http://localhost:3011 npm run smoke:workspace
# На заново подготовленной тестовой базе:
SMOKE_BASE_URL=http://localhost:3011 npm run smoke:profiles
SMOKE_BASE_URL=http://localhost:3011 npm run smoke:inbox
```

Проверка отказывается изменять базу без тестового маркера и не запускает реальные отклики. При изменении классов автоматизации повышайте `RUNNER_REVISION` в `runner.ts`: обновлённый экземпляр подхватывается между задачами, а действующая ручная проверка или незавершённый вход сохраняются.

При обновлении использованы официальные руководства: [Next.js 16](https://nextjs.org/docs/app/guides/upgrading/version-16), [Prisma 7](https://docs.prisma.io/docs/guides/upgrade-prisma-orm/v7), [Playwright Chromium](https://playwright.dev/docs/browsers).
